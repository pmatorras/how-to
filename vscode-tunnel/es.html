Configuración de VS Code Tunnel

Esta guía paso a paso explica cómo conectarse de forma segura a entornos de desarrollo usando VS Code Tunnels, y evitar problemas relacionados con TSPlus.

VS Code tunnels es una extension de Visual studio gratuita desarrollada por Microsoft. Para más información, consultar La guía de la aplicación.

Crear un usuario en Linux

Si necesitas una cuenta dedicada para usar VS Code Tunnel (para resolver problemas de configuración de GitHub), se puede crear antes de iniciar el túnel en la máquina remota.

Nota: En Ubuntu, adduser es la opción más sencilla para crear un usuario normal porque crea el directorio personal y guía la configuración inicial. 
sudo adduser NOMBRE_USUARIO

Si ese usuario también debe tener permisos de administración, añádelo al grupo sudo: 

sudo usermod -aG sudo NOMBRE_USUARIO

Después de crear el usuario, continúa con los pasos de configuración del túnel.

a) Mediante el interfaz de VScode

Paso 1: Iniciar el Tunnel en la Máquina Remota

Se puede iniciar el túnel de dos formas en la máquina host:

Abre la interfaz de VS Code abierta en la máquina, haz clic en el menú de Cuentas (abajo a la izquierda) y selecciona Turn on Remote Tunnel Access (Activar acceso a túnel remoto).

Selecciona si requieres que corra solamente con vscode abierto o siempre
Y elige la de realizar la conexión (yo he utilizado la cuenta de github de CTC)

Paso 2: Autentificar la Sesión

La CLI te pedirá que te autentiques con una cuenta de GitHub o Microsoft. Te proporcionará un código de dispositivo y una URL.

  1. Ve a https://github.com/login/device
  2. Autentificate.

Paso 3: Acceder a tu Entorno

Una vez autenticado, la terminal mostrará una URL única para tu máquina (ej. https://vscode.dev/tunnel/nombre-maquina).

Desde un Navegador Web:

Simplemente abre el enlace directamente. Puedes programar desde el propio navegador.

Desde tu VS Code Local:

  1. Instala la extensión Remote - Tunnels.
  2. Pulsa F1 y ejecuta Remote - Tunnels: Connect to Tunnel...
  3. Conectate con tu cuenta de github.
  4. Selecciona la máquina de la lista.
Una vez hecho esto, la configuración está guardada y puedes escribir código y ejecutarlo en tu ordenador local como si estuvieras en el ordenador en remoto!

💡 Nota importante sobre el flujo de trabajo

Una vez conectado, la configuración está guardada y puedes escribir y ejecutar código en tu ordenador local como si estuvieras en el servidor remoto. Sin embargo, ten en cuenta que si bien puedes Escribir código, usar la terminal, ver printouts (logs) y abrir imágenes o archivos directamente dentro del propio editor de VS Code, no puedes abrir el explorador de archivos de Windows/Linux para ver imágenes o documentos externos. Para eso, puedes guardar los archivos generados en una ruta compartida por el ordenador local y el remoto (OneDrive o una carpeta compartida en el servidor compartido ( p. ej. nassimulacion), o seguir usando TSPlus.

b) Usando la CLI (Recomendado para servidores sin interfaz gráfica)

Si el ordenador de conexión no tiene interfaz gráfica, inicia el túnel desde la terminal:

code tunnel
Durante esta primera ejecución:
  1. Acepta los términos de licencia (si te lo pide).
  2. Autenticación: Te dará una URL (ej. https://github.com/login/device) y un código. Ábrelo en tu navegador y autoriza.
  3. Nombre: Te pedirá asignar un nombre al túnel.

Una vez conectado, el proceso bloqueará la terminal. Presiona Ctrl + C para detenerlo antes de continuar.

Ejecutar como Servicio en Segundo Plano (Crucial)

Si solo usas el comando anterior, el túnel caerá al cerrar la sesión SSH. Para que sea persistente y sobreviva a reinicios, instálalo como servicio:

code tunnel service install

Puedes consultar los logs en cualquier momento con code tunnel service log.

Mantener el Servicio Activo por la Noche

Incluso después de instalar el túnel como servicio, puede desconectarse, ya que las sesiones de usuario de systemd están ligadas a las sesiones de inicio, y se detienen cuando el usuario cierra sesión o la sesión expira (normalmente tras ~12 horas). El sistema se reestablece una vez se inicia sesión,porque logind recrea la sesión de usuario en ese momento.

Para evitar tener que reiniciar la sesión, se puede ejecutar lo siguiente como root:

loginctl enable-linger NOMBRE_USUARIO

Esto le indica a systemd que mantenga la sesión del usuario activa aunque no haya ninguna sesión abierta, de forma que el servicio del túnel no se interrumpa.
